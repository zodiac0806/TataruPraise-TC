# 塔塔露誇獎（TataruPraise）

台服（TC）Dalamud 外掛。遊戲裡發生事情的時候，用塔塔露的克隆聲線喊**一句極短的提示**——
「完美收工！」「後面！」「排到了！」。**不是要太多對話，只是要有聲音。**
**純本機、內容健全（SFW）、預設全部關閉。**

> 📌 出廠就是這個形態：**每個情境一句、全部在 8 個字以內**。
> 想要長句誇獎的話，設定視窗「短句」分頁的「進階」裡可以把句長上限調高，再用 Gemini 擴充池。

指令：

| 指令 | 作用 |
|---|---|
| `/tataru` | 開啟設定視窗 |
| `/tataru test` | 試播一句（不受總開關限制） |

---

## 它怎麼運作

```
遊戲事件（Dalamud）─→ 逐情境冷卻 + 機率 ─→ 從情境的句子裡挑一句 ─→ 播事先合成好的 WAV
                                                        └─ 喇叭忙 ─→ 單格待播槽（比優先權）
```

**執行期完全不連網。** 句子與語音都事先準備好放在本機，遊戲中只是挑一句播檔案。
連網只發生在設定視窗裡那幾個按鈕（合成、預合成全部、擴充誇獎池、測試連線），
以及 IPC `Speak` 遇到**池裡沒有**的句子時（那條路會即時合成一次）。

資料放在外掛的設定資料夾底下（`%AppData%\...\Dalamud\Config\pluginConfigs\TataruPraise\`）：

- `pool.json` —— 依情境分類的誇獎句，格式 `{"情境": [{"text": "…", "wav": "cache/….wav"}]}`
- `cache/<sha1>.wav` —— 語音快取，檔名是句子的 SHA-1

第一次載入時如果池是空的，會灌入內建的預設句：**每個情境剛好一句**，全部在 8 個字以內、
都帶自然的中文標點。所以**不需要 Gemini 金鑰，裝好按一次「預合成全部」就能開始用**。

內建句只在整個池一句都沒有的時候才灌，**不會覆蓋你自己的池**；
版本更新新增的內建情境則是「缺哪個鍵補哪個鍵」，同樣不動既有的鍵。
反過來說，**改內建句對既有使用者沒有任何效果**——你的 `pool.json` 早就存在了。
要換句子就在設定視窗直接改（見下一節），或按「重置為預設池」。

## 設定視窗長什麼樣

**主畫面只有一件事：每個情境一句短句。**

| 欄 | 作用 |
|---|---|
| 啟用 | 這個情境要不要出聲。關掉＝內建觸發與 IPC `Praise` 都不出聲（`Praise` 回 `false`），而且**整列畫成灰字** |
| 情境 | 情境名（`pool.json` 的鍵，也是 IPC `Praise` 的參數） |
| 短句 | **直接編輯**。按 Enter 或點到別的地方就寫進 `pool.json` |
| 冷卻（秒） | **直接編輯**，顯示的是**生效值**（自訂 → 內建 → 全域）。旁邊的 `×` 只在有自訂時出現，按下去就退回預設 |
| 語音 | 有／無。🔴 沒有 WAV 的情境**觸發時是靜默的**，所以這一欄畫在列上不藏 tooltip |
| 合成 | 把這個情境還缺語音的句子送去橋接 |
| 試播 | 現在播一次。總開關與「啟用」關著都照播，而且**不會推遲真正的冷卻** |

> 🔴 開關有**兩層**：「觸發」分頁的逐觸發勾選（事件層）與這裡的「啟用」（情境層），**兩層都開才會響**。
> 情境層也管別的外掛用 IPC `Praise` 叫它；IPC `Speak`（呼叫端自己指定句子）不受它影響。

> 🔴 在「短句」欄改字並送出，會把那個情境收成「**只有你打的那一句**」，
> 舊句與它們的 WAV 一起刪掉，**不可回復**。同一句話還掛在別的情境底下時 WAV 會留著。

表格下面是「預合成全部」與「重置為預設池」。多句、句長上限、Gemini 擴充這些
**加上去的能力**全部收在預設收合的「進階」裡，不碰它也能用。

視窗頂部有一列狀態：「語音快取 N/M 已合成」與「9882：上次合成成功／失敗（時間）」。
🔴 那一列**不會自己去連 9882**，它顯示的是上一次真的送出去的合成留下的結果。

## 資訊列（DTR）

伺服器資訊列上有一格「塔塔露」：**點一下直接切換總開關**（立刻存檔，不是暫停）。
圖示 ○＝開、🚫＝關。tooltip 列出最近 5 次觸發（時間／情境／句子）與「沒有語音的情境數」。

> 🔴 DTR 的文字是遊戲的**原生文字節點**畫的，不是 ImGui——所以這裡用的是遊戲自己的圖示字元
> （`SeIconChar`），FontAwesome 那套字型在原生節點上畫不出來。

**表上的「類型」只影響出聲的優先權**（見下面的「同時來很多事」），句長全部都是極短提示：
上限 12 字、警示 8 字、提醒 10 字。**情境描述裡就寫明了要多短**，用 Gemini 生句時會照著要。

> 🔴 所有內建情境的**句長下限都放寬成 2 字**。全域下限 6 字是拿來擋模型吐出來的殘句的，
> 套到「後面！」（3 字）、「完美收工！」（5 字）這種句子上會把它們**全部當成殘句丟掉**，
> 而且看起來像模型壞掉。

還可以自己**新增情境**（「短句」分頁 →「進階」→「新增情境」），鍵名就是 IPC `Praise` 的參數。
每個情境都有：

- **情境描述** —— 生句時寫成「遊戲情境：<這段話>。」餵給模型。內建情境有預設描述，可以自己改寫；
  改寫存在**外掛設定檔**，不在 `pool.json`（所以「重置為預設池」不會把描述一起清掉）。
- **句長上限覆寫** —— 只給這個情境用的上限，0＝沿用全域（出廠 12）。
  🔴 提示詞跟模型要的字數範圍會**跟著這個上限一起調整**：上限 12 → 要 2～10 字，
  上限 28 → 要 12～25 字。兩邊對不起來的話良率會掉到接近 0，而且看起來像模型壞掉。
- **冷卻覆寫** —— 只給這個情境用的冷卻秒數。**改在「短句」表格那一列的「冷卻（秒）」欄**（不在「進階」裡），
  填 0 或按旁邊的 `×` ＝清掉自訂、退回內建／全域的預設。
- **啟用** —— 同一張表最左邊的勾選，關掉就完全不出聲（連 IPC `Praise` 也是）。

內建情境**刪不掉**（下次啟動會連同內建句一起補回來）；自訂情境有「刪除」鈕，兩段確認，
刪掉句子但**保留 WAV 快取**（同一句可能還掛在別的情境底下，而且加回來時可以直接重用）。

> 🔴 **版本更新新增的內建情境會自動補進既有的 `pool.json`，而且是帶著內建句補的**，不是補一個空陣列——
> 補成空的話 IPC 呼叫端會永遠拿到 `false`，完全沒有錯誤訊息。


## 觸發

有內建觸發的情境列在下面，**全部預設關閉**，另外還有一個總開關。
命中後要先過**該情境的冷卻**，再過觸發機率（出廠 100%；警示與內建通知不擲骰），
最後還要過那個情境在「短句」分頁的**「啟用」勾選**（🔴 兩層都開才會響）。

> **冷卻的優先序：情境自訂覆寫 → 內建覆寫（通知 5 秒、警示 15／10／10）→ 全域（出廠 10 秒）。**
> 🔴 計時器是**逐情境分開算**的：「潛艇」的冷卻不會擋到「血量低」，AutoRetainer 多角色連跑時
> 後面幾個角色的通知也不會被前一個吃掉。

### 同時來很多事：單格待播槽

喇叭一次只播一句。第二句來的時候**不會打斷正在播的那一句**，而是進一個**只有一格**的待播槽；
播完立刻接上。槽裡已經有東西時比優先權，**輸的那個丟掉**（記一行 Debug）。

| 優先權 | 情境 |
|---|---|
| 0（最高） | `血量低` |
| 1 | `敵人從後面來` |
| 2 | `被大量敵人標記` |
| 10 | 所有通知（含自訂情境與別的外掛用 IPC 叫的新鍵） |
| 20（最低） | `副本完成`、`升等`、`登入`、`Gil里程碑` |

- 同優先權**先來的贏**：後到的一律覆蓋會讓連續事件只聽得到最後一個。
- 槽裡**只放純量**（情境鍵、句子、WAV 路徑、優先權 int），不放任何跨幀會被改寫的原生東西。
- IPC `Speak` 與設定視窗的「試播」**不進待播槽**：那是明確要求的當下那一句，遲到兩秒更奇怪。

| 觸發 | 來源 | 備註 |
|---|---|---|
| 副本完成 | `IDutyState.DutyCompleted` | **首次通關**改用「首次通關機率」（預設 100%）；見下 |
| 升等 | `IClientState.LevelChanged` | 只有等級**真的往上跳**才算；登入時的等級回報、切職業的等級回報都不觸發 |
| 登入 | `IClientState.Login` | 預設**只在當天第一次登入**才誇（可關成每次登入） |
| Gil 里程碑 | 每 5 秒讀一次身上的 Gil | 跨過設定的整數倍（預設 100 萬）才觸發；登入後第一次讀到的數字只當基準 |

### 戰鬥警示（三條，只讀狀態、只出聲）

🔴 **不做任何遊戲操作**——不施放、不走位、不改目標，只是唸一句 2～6 字的短句。
每 0.25 秒輪詢一次；物件表的包裝**當幀用完即丟**，跨輪只留 `GameObjectId`（ulong）與距離（float）。

| 警示 | 判定式 | 預設 |
|---|---|---|
| `血量低` | `InCombat` 且 `CurrentHp * 100 / MaxHp < 門檻`，且血量曾回到門檻以上（遲滯） | 門檻 30%、冷卻 15 秒 |
| `被大量敵人標記` | **僅 PvP**：`StatusFlags.Hostile` 的 `IPlayerCharacter` 中，`TargetObjectId == 我` 的個數 ≥ N | N＝3、冷卻 10 秒 |
| `敵人從後面來` | **僅 PvP**：敵對玩家在後半平面（前方向量 `(sin r, cos r)` 與「我→他」內積 < 0）、水平距離 ≤ R、且**比上一輪更近**（至少 0.05 碼）的個數 ≥ N | R＝15 碼、N＝2、冷卻 10 秒 |

- 「正在接近」需要上一輪的距離當基準，**剛進視野的第一輪不算**。離開 PvP／登出時整份基準清空。
- 🔴 警示**不擲觸發機率骰**（等同 100%）：30% 機率的警示比沒有還糟。冷卻照走。

### 內建通知（四條，只讀狀態、只出聲）

🔴 **不會替你按任何按鈕**——不同意、不拒絕、不接受交易，只是喊一聲。
跟警示一樣**不擲機率骰**，但照走各自的冷卻（5 秒）。

| 觸發 | 情境鍵 | 判定式 | 備註 |
|---|---|---|---|
| 被密語 | `被密語` | `IChatGui.ChatMessage` 的 `type == XivChatType.TellIncoming` | 🔴 **只看聊天類型這個列舉值，一個字都不比對**。自己送的密語是 `TellOutgoing`，不會自己喊自己 |
| 副本排到（內建） | `副本排到` | `IClientState.CfPop` | 跟 NotificationMaster 用 IPC 叫的**是同一個鍵**；兩邊都開也只會聽到一聲（冷卻 5 秒吸掉第二次） |
| 組隊邀請 | `組隊邀請` | addon `_NotificationParty` 由不可見變成可見 | ⚠️ 見下面的警告 |
| 交易請求 | `交易請求` | addon `Trade` 由不可見變成可見 | ⚠️ **自己主動發起交易時也會響**（分不出誰發起的） |

> 🔴 **`被密語` 與 `私訊` 是兩個不同的鍵**，刻意的：`私訊` 沒有內建觸發、留給
> NotificationMaster 之類的外部呼叫端；`被密語` 是這個外掛自己訂閱聊天事件觸發的。
> 兩邊都開就會聽到兩次——想只聽一次就關掉其中一邊。

> 📌 **名字的離線證據**（掃台服執行檔＋反組譯，先用 `SelectYesno`／`Trade`／`_PartyList`／
> `ContentsFinderConfirm` 校準過，另加合成負例）：執行檔裡**沒有** `PartyInvite`／`InviteReply`／
> `_PartyInvite`（各 0 次）。通知彈窗是一張**指標陣列**（基底 `0x142123DA0`、每格 8 bytes），
> 長度 34 是從關閉函式的界限檢查 `cmp edi, 0x22` **讀出來**的、不是數出來的；
> `_NotificationParty` 是**第 12 格**。同表還有 `_NotificationFriend`（好友）、`_NotificationFcJoin`（部隊）、
> `_NotificationLinkShell`（通訊貝）、`_NotificationReadyCheck`（準備確認）…語意一致；台服 `Addon.csv` 第 170~172 列
> 正是連號的「入隊邀請／好友申請／通訊貝邀請」。`Trade` 是主 addon 表第 44 筆，而且客戶端裡
> **根本沒有交易請求專用彈窗**，所以收到請求時開的就是 `Trade` 本身。
> **但「第 12 格＝收到組隊邀請」這最後一環還沒有實機驗過。**
>
> 🔴 **刻意不用 `IAddonLifecycle` 的 `PostSetup`，改成每 250ms 輪詢可見性、取上升緣。**
> 客戶端顯示通知彈窗的路徑是**先用名字查有沒有既存的、查到就重用**，只有查不到才配置新的；
> 關閉走 `AtkUnitBase::Close(false)`，到底有沒有真的釋放掉離線判不出來。如果沒有釋放，
> `PostSetup` 就**只有登入後第一次邀請會觸發**，之後全部靜默——而且看起來會像「冷卻沒到」
> 或「機率沒中」。改成輪詢之後這個問題整個不存在。（旁證：TCToolbox 對同一族的
> `_NotificationCircleBook` 用的也是 `PreDraw` 不是 `PostSetup`。）

> ⚠️ **組隊邀請與交易請求靠的是 addon 名字**，而 addon 名對不上的失敗形狀是
> **不響、不崩、也沒有錯誤訊息**（`IAddonLifecycle` 對沒出現過的名字不會抱怨）。
> 所以真的沒響的時候，第一件事是確認 `TriggerWatcher` 裡那兩個常數（啟動時的 `Information` 記錄有印出來），不是去查冷卻或機率。
> 🔴 **刻意不用 `SelectYesno`**：那是通用的是／否對話框，從丟棄道具到退出副本都用它，
> 拿它當判準會變成什麼都喊一聲。而且組隊邀請的 `SelectYesno` 是**按下彈窗按鈕之後**才出現的
> 第二層（`Addon#120` 加入／`Addon#121` 拒絕），不是彈窗本身。

**首次通關**：`DutyCompleted` 給的是 territory id，外掛用 Lumina 的 `TerritoryType` 表反查
`ContentFinderCondition`，把通關過的 CFC id 記進設定。第一次看到某個副本就用「首次通關機率」，
之後走一般機率。

- 🔴 反查不到（非副本場景、或表讀不到）就**照一般副本處理**，不記、不誤判成首通。
- ⚠️ 「通關過沒有」是**這個外掛自己記的**，不是遊戲的通關紀錄——裝外掛之前跑過的副本，
  第一次再跑照樣算首次通關。

**當天第一次登入**：以**本機日期**算。日期戳只在**真的出聲之後**才寫——冷卻擋掉、機率沒中、
池裡沒有已合成的句子都不算今天用掉了，所以換角色重登還是有機會聽到。

> 🔴 **刻意不做**任何靠聊天訊息**文字比對**的觸發（成就、製作大成功之類）。
> 台服的中文字面沒辦法離線確定，照國際服寫死一定錯，而且錯法是靜默的。
> 「被密語」訂閱的是同一個聊天事件，但判準只有 `XivChatType` 這個**列舉值**，不碰訊息內容。


## 語音橋接（前提）

語音來自本機的 **GPT-SoVITS 橋接**（`gsv_bridge`，預設 `http://127.0.0.1:9882`），
背後是跨語言克隆（日配參考音訊 → 中文輸出）。橋接與遊戲同機就用 `127.0.0.1`；
跑在另一台機器的話，那邊要把橋接與 api_v2 綁 `0.0.0.0`、防火牆放行 9882，設定裡填區網 IP。

外掛只用到兩個端點：

```
GET  {host}/speakers
  → [{"name":"塔塔露","voice_id":"塔塔露"}, …]

POST {host}/
  {"text":"要念的中文", "text_lang":"zh", "ref_audio_path":"./参考音频/塔塔露.wav"}
  → 200，body 就是 WAV bytes
```

只送這三個欄位就好：橋接會依 `ref_audio_path` 的檔名對到聲線，自動補參考音訊、逐字稿、
`prompt_lang` 以及全部穩定化參數。錯誤語意：`404` = 聲線沒設定、`502` = 橋接背後的 api_v2 連不上。

> 🔴 送去合成的句子**必須含自然的中文標點**（逗號、頓號、句號、驚嘆號）。
> 沒有標點的長句會讓聲線越念越高變成怪腔——這是實測結論，不是風格偏好。
> 所以擴充池時會把沒有標點的生成結果直接丟掉。

**橋接連不上的時候外掛只是不出聲，不會崩、不會卡遊戲。**

## 擴充誇獎池（Gemini，選用）

**這是可選的。** 不填金鑰、不按這裡的任何按鈕，外掛照樣完整可用——
出廠的內建句就是完成品，主流程是「裝好 → 按『預合成全部』 → 到『觸發』分頁開想要的事件」。

設定視窗 →「短句」分頁 →**展開「進階」** → 填 Gemini API 金鑰 → 按「全部擴充」。
會對**每一個情境**各要一批新句子（出廠每個情境 5 句），要求模型輸出 JSON 陣列，去重後寫進 `pool.json`。
進階的情境表格上每一列也有自己的「生成」，只補那一個情境。
接著按「預合成全部」把新句子逐句送去橋接合成。

> ⚠️ 擴充之後那個情境就會有**多句**，播的時候是**隨機**挑一句。
> 主畫面的「短句」欄位這時顯示的是第一句，語音欄會改印「N/M 句」提醒你。
> 在那裡改字並送出會把情境收回「只有一句」。

- **句長上限（全域出廠 12 字，滑桿 12～60；每個情境可以自己覆寫）**：提示詞要求的字數範圍
  **跟著有效上限自動算**（12 → 2～10 字，28 → 12～25 字），只講一句話，
  生回來超過上限的句子會被**直接丟掉**（丟了幾句顯示在「上次結果」那一行，也寫進記錄檔）。
  上限 ≤12 時提示詞還會換一套措辭（「不要逗號、只有一個結尾標點」）。
  字數不含空白、中文標點算在內。
  🔴 這個上限**只擋新生成的句子**，`pool.json` 裡已經有的句子不會被動到；要清掉超長的，
  按滑桿下面的「移除超過各情境上限的句子」（先列出有幾句、再確認一次才刪，連 WAV 快取一起刪，不可回復）。
- 金鑰欄位是**遮罩**的，旁邊會標「（已設定）／（未設定）」——遮罩過的欄位裡「空的」與「填了但看不見」長得一樣。
- 預設模型 `gemini-3.5-flash-lite`，可自填。其他可用：`gemini-flash-lite-latest`、`gemini-3.6-flash`。
  **`gemini-2.x-flash` 系列對新金鑰已停用**（回 404），別填。
- `429`（額度）／`503`（過載）會指數退避重試最多 3 次；其他錯誤直接放棄。失敗只寫 `Information` 級記錄，不出聲、不彈窗。
- **金鑰存在這個外掛的設定檔裡**（Dalamud `GetPluginConfig`），不進版控、不會寫進記錄檔。

> 設定裡的「文字後端」列舉保留了「雲端即時」與「本機即時（Ollama）」兩個值，
> 但**第一版沒有實作**，選了等同純池模式。

## IPC 契約

其他外掛可以直接呼叫。契約名逐字定義在 `TataruPraise/IpcContract.cs`。

> 🔴 **這四個名字不會改。** Dalamud 的 CallGate 是純字串比對，改名不會有錯誤訊息，
> 呼叫端只會拿到「沒有人註冊」——靜默斷線。要換語意會開新名字，舊的留著。

| 契約名 | 簽章 | 行為 |
|---|---|---|
| `TataruPraise.Speak` | `Func<string, bool>` | 念這一句。先查語音快取，沒有就背景送 9882 即時合成（逾時 10 秒）並順便存進快取。**不吃冷卻、不吃機率**，但吃總開關與「同時只播一句」。**不進待播槽**：喇叭忙就直接回 `false`。回傳是「有沒有排進去」，不代表真的出得了聲。 |
| `TataruPraise.Praise` | `Func<string, bool>` | 從指定情境的句子裡挑一句已合成的來播（喇叭忙就依優先權進待播槽）。**不看事件開關、不看機率，但吃冷卻**與總開關。情境字串＝`pool.json` 的鍵（見下）。**未知情境回 `false`**，並在記錄檔印一次 `Information`（同一個情境只印一次，不會洗 log）。 |
| `TataruPraise.IsAvailable` | `Func<bool>` | 總開關開著**而且**池裡真的有已合成語音的句子。 |
| `TataruPraise.IsAvailableFor` | `Func<string, bool>` | **指定情境**現在有沒有辦法出聲：總開關開著＋該情境沒被使用者關掉＋該情境至少有一句已合成語音（不看冷卻）。用來補 `IsAvailable` 只看「整池有沒有任何情境能播」的洞。 |

呼叫範例：

```csharp
var speak = pluginInterface.GetIpcSubscriber<string, bool>("TataruPraise.Speak");
try
{
    speak.InvokeFunc("前輩，這一手漂亮！");
}
catch (Exception)
{
    // 對方沒安裝／沒載入時 InvokeFunc 會擲 IpcNotReadyError，呼叫端自己要接。
}
```


### 給呼叫端的情境鍵

**鍵名逐字固定**，跟 IPC 契約名一樣不會改。

完整清單見上面的「情境」表（那張表由 `tools/gen_category_table.py` 從原始碼產生）。

```csharp
// 呼叫端（例如 AutoRetainer 的潛艇回港處理完之後）
private ICallGateSubscriber<string, bool>? tataruPraise;

tataruPraise ??= pluginInterface.GetIpcSubscriber<string, bool>("TataruPraise.Praise");
try
{
    tataruPraise.InvokeFunc("潛艇");   // 回 true ＝ 已排進播放
}
catch (Exception)
{
    // 沒安裝／沒載入 → IpcNotReadyError，忽略就好。
}
```

回 `false` 有幾種情形，都不是錯誤：總開關關著、還在冷卻、上一句還在播、
這個情境沒有任何**已合成語音**的句子、或者**情境名不存在**（最後這種會在記錄檔印一次
`未知情境「X」`，同一個情境只印一次）。

dotnet build TataruPraise/TataruPraise.csproj -c Release -p:DalamudLibPath=D:/ffxiv-tc-port/Dalamud/bin/Release/
